# 检查结果闭环与站内提醒：实施与验收

本轮实现检查单、PDF 报告修订、医生复核、后续照护任务、患者告知，以及持久化站内提醒。现有部署默认关闭新建流程和投递；关闭后仍可授权读取已保存记录。

## 启用与回退

安装 `backend/requirements.txt` 中的依赖后，在后端环境中设置：

```text
NANTINGALE_TEST_RESULTS_ENABLED=true
NANTINGALE_NOTIFICATIONS_ENABLED=true
```

两项默认均为 false。启动时运行 `app.result_schema.migrate_results`，仅创建新增表、索引、归属约束触发器和缺失的新增列，不重置数据库、不运行种子重建。Windows 的时区解析使用新增的 `tzdata==2025.2`。

诊所 Admin 在“Reminders & delivery”配置时区和提醒间隔。初始 24 小时设置仅用于合成演示。现有有效任务会被纳入提醒；已结束任务与已撤回、被替代的指引不会补发历史通知。策略修改用于后续安排，已经安排的任务保留其截止时间。

回退时将两个环境开关设为 false 并重启。保留所有表和历史记录，不执行种子重置或删除。生产模式继续受既有 SQLCipher、HTTPS 与其他启动检查约束；本轮没有部署或生产验证。

## 数据与业务规则

- `TestOrder` 关联原开单 Event、患者、诊所、跟进人、复核医生、预计时间和并发 revision。旧 Care Task 可由用户明确选择关联，不从病历文本自动推断。
- 首份报告产生一个 `test_result` Event。追加版本、复核和沟通继续归属于该 Event；时间轴不将每次修改伪装成新就诊。
- `TestReport` 保存不可变 PDF BLOB、SHA-256、出具时间、上传人和版本，另有独立 external-report Artifact。外部报告作者与上传人分开；报告不标成 AI 生成。
- PDF 检查后缀、声明类型、文件签名、结尾和 10 MiB 大小。专用 JSON 上传接口允许有限的 base64 开销，其余接口继续使用原请求体上限。认证下载返回附件与 `no-store`，没有公共文件地址。
- `TestReview` 与 `TestCommunication` 追加独立 Artifact。当前状态由有效报告、当前医生复核和有效沟通证据推导。
- “观察随访”“需要行动”均必须创建有负责人、截止时间的后续 Care Task。结果处理可以先关闭；整个结果工作流在后续任务结束前保持 active。
- 现有 Task 的工作流/种类/角色唯一约束保留。每个检查阶段复用一条有审计记录的 Task；报告修订时重新打开阶段 Task。后续独立 Care Task 使用既有 care_action_chain，并由复核记录的显式外键关联，结果主链的完成判定检查这些后续任务。
- 普通任务 transition 不能完成报告跟进、结果复核或结果告知阶段。临床操作通过专用检查接口执行。
- 指引草稿在服务端绑定具体复核 ID。发布/更正检查绑定是否仍有效；站内告知绑定具体发布版本。报告修订或撤回使旧发布失效，旧草稿也不能直接发布。指引撤回/更正会在同一事务中重新打开待告知任务。
- 电话未接通、留言或未确认送达不关闭。已读通知不会完成任务，患者指引回执也独立保存。
- 幂等操作记录、父检查单条件更新、报告/复核/任务/审计/通知任务在同一事务内保存。同一个幂等键的不同内容返回 409。

## 提醒实现

`NotificationJob` 是持久 outbox，`InboxNotification` 是用户收件箱记录。业务提交时写入通知安排，worker 默认随 60 秒后台巡检运行。领取使用条件更新、唯一租约和两分钟租约期限；异常退出后可恢复。

投递前复查事项版本、活动状态、诊所和接收人当前角色。通知插入与 job 成功状态在同一事务提交，唯一键保证同一事项版本/接收人/阶段只展示一次。初次、到期和升级均有界；普通任务开始执行不会重复发送分配提醒。

失败按 1、5、15、60 分钟重试，第五次失败后进入 Admin 失败列表。Admin 可重新安排投递，不能编辑临床目标。错误只保存固定错误码。完成或失效事项取消旧安排，并将已显示通知标为已解决/被替代。

原负责人保留。逾期升级记录进入医生共享工作队列；负责人失去权限时改由同诊所医生接收。没有可用医生时，任务保留阻塞元数据，Admin 只看运营计数。现有患者报告升级任务机制继续复用，不由通知系统再建立一套临床升级任务。

新调度时间采用 UTC；旧无时区期限按诊所时区解释，默认 Asia/Singapore。未批量改写历史 Event 时间。提醒不是实时危急值召回，也不证明接收人已理解或已被联系到。

## 界面

- 临床患者工作区增加 Tests，按待报告、待复核、待告知、已处理和取消分组；就诊详情提供开单入口。
- 可选择同诊所负责人、上传 PDF、追加/撤回版本、提交复核、建立后续任务、发布患者指引并记录沟通。
- Work inbox 和临床任务卡直接进入对应检查。通知入口覆盖临床工作区和患者页面，显示未读数，支持分页和标记已读。每 30 秒在可见页面刷新，重新获得焦点时刷新。
- 患者通知只用安全文案，进入被授权的具体指引版本；过期链接提示使用当前指引。
- Admin 页面展示策略、待处理数量、最老待处理时间、失败列表、阻塞计数和最近巡检时间，不展示报告正文或内部复核结论。

## 验收记录

自动化覆盖：电话/站内两条关闭路径、护士复核拒绝、患者/Admin 报告读取拒绝、跨诊所拒绝、普通任务不能绕过检查、指引撤回重开、报告修订保留历史、重复提交、双医生竞争、报告修订与复核竞争、后续任务独立完成、PDF 10 MiB 边界、Copilot 排除、功能关闭后的授权读取；通知去重、两个 worker、租约恢复、失败耗尽/恢复、已读隔离、时区和无期限任务。

全量回归：756 passed、2 个既有可选本地语音输入测试 skipped。最后的显示时区/重复文件处理补充改动另跑相关回归，23 项通过。前端类型检查、3 个 Node 测试和 118 模块生产构建已通过。密钥扫描和 diff 空白检查通过。

真实 Chrome 使用独立临时合成数据库与真实 Cookie Session，未写入项目工作数据库。已观察：医生登录和开单、预置报告后的复核、未接通保持待告知、成功告知关闭、通知 7→6 已读变化、Admin 策略和运营界面、390 px Admin 布局无横向溢出、患者安全通知和具体指引打开、护士从 Work inbox 直达对应检查且没有医生复核按钮。

**浏览器硬门尚未全部通过**：Chrome 扩展未开启文件 URL 访问权限，文件选择器拒绝自动选择合成 PDF。因此后续浏览器复核使用测试夹具预置报告，不能算真实上传验收通过。下载按钮已触发，但浏览器工具未收到下载完成事件；认证下载内容与响应头已通过接口测试，浏览器文件落盘仍未确认。完整发布验收需补齐这两项。

本轮没有外部消息、OCR、LLM 报告解释、临床验证、生产发布或 Git 提交。
